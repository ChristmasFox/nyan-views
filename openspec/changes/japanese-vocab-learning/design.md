## Context

- 仓库为 Next.js（App Router）+ TypeScript；现有首页曾承担大屏演示、DB 计数与 Redux 测试，与日语学习产品目标不一致。
- 产品共识（见 `proposal.md`）：无登录；词表 JLPT 标签为近似；语音必选于「语音模式」内，判分先宽松；语音模式流程为先识别 → 重试 → 打字过关；打字模式仅文本作答；入口先选模式。

## Goals / Non-Goals

**Goals:**

- 用**成熟 SRS**（如 SM-2 或 FSRS 的现成实现或自研调度与成熟公式一致）管理复习间隔；卡片 UI 支持正反面翻转或叠卡动效。
- **发音**：优先 Web Speech API（`speechSynthesis`）快速落地；可预留切换为预生成音频 URL 的抽象。
- **语音作答**：`SpeechRecognition`（或等价 API）取**识别文本**，与期望表记/读音做多形式规范化后做**字符串相似度**（如 Levenshtein 归一化、包含匹配、多候选答案）；阈值配置化（目标为宽松通过，例如高容错），第二阶段再收紧或接云端 ASR。
- **日文输入**：用户自带 IME；服务端/客户端校验前做 Unicode 规范化（如 NFKC）、假名统一（かな/カナ）及可配置的「可接受答案」列表。
- **进度与打卡**：`localStorage` 与/或 **IndexedDB** 存 SRS 状态、每日完成记录、streak；日期按 `Intl` 或本地时区午夜切日。
- **响应式**：移动优先断点，触控友好按钮与卡片，语音需 HTTPS。

**Non-Goals（本阶段）：**

- 用户账号、服务端同步、社交排行榜。
- 词表学术级校对或与单一官方大纲严格对齐。
- 声学级发音评分（非识别文本路径）。
- 离线 PWA（可作为后续变更）。

## Decisions

1. **SRS 库**：优先选用维护良好的开源 SRS/FSRS TypeScript 实现；若无合适依赖则实现最小 SM-2 兼容调度，并抽象 `schedule(card, grade)` 便于替换 FSRS。
2. **模式入口**：每次进入「学习会话」前选择**打字**或**语音**；会话内不切换模式（减少状态组合）。全局可记忆上次选择（localStorage）。
3. **首页与演示代码**：原大屏相关 UI 迁至 `LegacyDemoHomePage.tsx`（或同名），**不由** `app/page.tsx` 引用；首页组件仅展示学习入口与说明。
4. **路由**：MVP 可在 `/` 放营销式首页；实际训练页使用 `/study`（或 `/(learn)/study`）单页应用式流程，便于后续扩展。
5. **音效**：短 MP3/OGG 静态资源 + Web Audio 或 `<audio>`；提供「关闭音效」与尊重 `prefers-reduced-motion`（可同步减弱动画与音效）。
6. **语音识别失败兜底**：语音模式内在重试次数用尽或用户主动选择后进入**同一题**的打字过关，SRS 评级逻辑与打字模式一致（MVP 不区分「仅打字过关」与「语音直接过」；可选字段留待二期）。

**备选方案（未采纳）**：仅云端 ASR——延迟与成本较高，推迟到第二阶段。

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| 浏览器日语识别质量参差 | 宽松阈值 + 重试 + 打字兜底；文档说明环境要求 |
| 无登录导致换机丢数据 | 二期导出/导入 JSON；提案已接受 |
| 词表标签不精确 | 允许后续批量重标，数据结构保留 `level` 字段 |
| TTS 音色不一致 | 二期换统一音频源 |

## Migration Plan

1. 合并本变更后：`app/page.tsx` 仅渲染日语学习首页；移除对 `displayGroups` 的查询（或保留 API 供 Legacy 组件将来在独立路由调试时使用）。
2. 若需恢复演示首页：临时将 `page.tsx` 改回导入 `LegacyDemoHomePage` 并恢复数据获取即可。
3. 数据库 schema 无需为 MVP 迁移；大屏功能未删除，仅脱离默认首页。
